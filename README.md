# Древлепуща

Исследование древнего леса от третьего лица в художественном языке иллюстраций Толкина. Первая цель — маленький путник среди огромных стволов, корней и нависающих крон; затем короткий маршрут от западного входа к Bonfire Glade.

Дальняя цель из исходного комплекта — большой исследуемый мир Средиземья и атлас. Древлепуща проверяет, каким способом его действительно посильно создавать.

**Состояние на 8 сентября 2026 года:** M0 — запускаемый стенд третьего лица — принят Александром. Есть герой ростом 1,1 м, движение по рельефу, камера, стволы, низкая арка и склон. Камера сохраняет выбранные пользователем ракурс и дистанцию; закрывающие героя объекты плавно становятся полупрозрачными. WebGPU работает по умолчанию; WebGL2 сохранён как запасной режим. Результаты проверок и сравнение API — в [отчёте M0](qa/M0.md). Это техническая сцена с условными формами; художественный лес относится к M1.

[Открыть лес M1](https://amchercashin.github.io/drevlepuscha/?scene=m1) · [Открыть опубликованный стенд M0](https://amchercashin.github.io/drevlepuscha/) · [GitHub](https://github.com/amchercashin/drevlepuscha)

Удержание **Shift + WASD** включает тестовую скорость **15 м/с (54 км/ч)**; отпускание Shift возвращает ходьбу 1,85 м/с. Работают оба Shift, скорость по диагонали не увеличивается. Проверено в M1 на WebGPU: за секунду около 15 м с каждым Shift и 1,85 м после отпускания; ошибок сцены и отклонения камеры нет. `npm run check` и сборка прошли.

Разрешение учитывает пропорции окна и плотность экрана. По умолчанию — «Высокая» чёткость с бюджетом 2560 × 1440 пикселей (3,7 Мп), без ограничения ширины 1280. В «Проверке стенда» доступны 0,9 / 2,1 / 3,7 Мп и «По экрану» (Retina до 2×, сторона до 8192 или лимита GPU). Выбор сохраняется в браузере. Для окна 3440 × 1440: примерно 2968 × 1242 по умолчанию или полные 3440 × 1440 в режиме «По экрану» при DPR 1. На WebGPU проверены окна 3440 × 1440, 1920 × 1080, 900 × 1200, Retina 2× и сохранение выбора после перезагрузки. Это фиксированные уровни качества, без автоматического снижения по FPS; прежние замеры 60 FPS при 1280 × 720 не подтверждают производительность высокого разрешения.

Атмосфера M1 по умолчанию — ясный лес с лёгкой дальней дымкой (EXP2, плотность 0,004 вместо 0,023). Прежний плотный туман выбирается в «Проверке стенда → Атмосфера леса → Туманный лес»; новая загрузка снова открывает ясный вариант. Переключение проверено на WebGPU, ошибок нет; `npm run check` и сборка прошли. В ясную погоду заметнее конечность участка и повторение одной модели.

**Александр выбрал основной путь: концепт Codex → Meshy Smart Topology → игровая модель.** Обычный M1 теперь открывается с деревом А. [Гулять по лесу](https://amchercashin.github.io/drevlepuscha/?scene=m1) · [Концепт, модель и LOD А](https://amchercashin.github.io/drevlepuscha/tree.html?model=meshy-a) · [Сравнить с Б](https://amchercashin.github.io/drevlepuscha/tree.html?model=meshy-b).

Проверены оба пути из одного приватного рисунка: А — концепт встроенного генератора Codex, Б — концепт Meshy `nano-banana-2`. Обе модели с текстурами действительно экспортированы, скачаны и импортированы в сцену. Общий расход Meshy — **36 кредитов**: 6 за концепт Б и по 15 за две модели; исправления и вариации выполняются локально. Настроены официальный MCP и воспроизводимый REST-скрипт с защитой от повторной отправки оплаченной задачи. Участок — **512 × 640 м, 4967 деревьев**. Одна модель получает воспроизводимые вариации: высота примерно **11–18 м**, ширина **45–78%** исходной, независимая глубина, полный поворот и небольшой наклон до ±2° по каждой оси. ID и позиции сохранились. Это разнообразие пропорций, а не новые схемы ветвления. Исходные 18 м выбраны при подготовке; масштаб не вычислялся по человеку на картинке. Четыре контрольных дерева имеют заданные пропорции.

Для А добавлены **разные оттенки деревьев**: плавные группы около 48 м и небольшие индивидуальные отличия по seed. Светлота листвы меняется в пределах ±8%, коры — ±4%; оттенок и насыщенность листвы меняются сдержанно, до расчёта освещения. Общие геометрия, текстуры и материалы сохранены. В «Проверке стенда» есть переключатель для сравнения; при новой загрузке вариации включены. [Кадр с вариациями цвета](qa/evidence/meshy/a-color.png). Проверены только А: включение/выключение, восстановление тех же пикселей после включения, дальние группы и прозрачность препятствий; число вызовов отрисовки в контрольных точках не изменилось. Новый длительный замер FPS не проводился.

Исправлены зелёные стволы дальних LOD: прежнее упрощение нарушало UV атласа. Теперь дальние модели используют перенесённые цвета вершин, а самые дальние кроны — замкнутые объёмы. Ближняя текстура Meshy сохранена. Деревья стали уже и в среднем ниже; корни глубже посажены с учётом рельефа и наклона. [Кадр после исправлений](qa/evidence/meshy/a-forest.png).

Отрисовка сохраняет общую геометрию и instancing. Ячейки 64 × 64 м переходят к подробной отрисовке на 110 м и обратно к дальним группам на 125 м. Для выбранного дерева — три общих набора геометрии и 80 маленьких копий дальнего LOD для групп. Дальность камеры 1000 м. Переход LOD длится 0,25 с с взаимодополняющей маской; реальные препятствия перед героем плавно становятся полупрозрачными. Камера не меняет выбранный ракурс или дистанцию. Участок конечный; общих моделей рощ и сетевого стриминга ещё нет.

Проверки: `npm run check` — **85 тестов**, сборка, четыре целевые браузерные проверки на WebGPU. Экспорт исходников, нормализованных моделей и обоих LOD прошёл Khronos glTF Validator без ошибок и предупреждений. А после исправлений: медиана **16,7 мс**, P95 **17,7 мс**, кадров длиннее 33,34 мс — **0**; максимум в контрольных точках — 407 623 треугольника и 21 вызов отрисовки. Это выше предварительного ориентира 300 тысяч треугольников. [Замеры](qa/evidence/meshy/performance.json) относятся к M3 с 8 ГБ, WebGPU, 1280 × 720, прогреву 30 с и проходу 60 с на вариант; они не подтверждают высокое разрешение, длительный нагрев или Windows-рендер.

Ограничения: дальние кроны приближённые; соседние кроны могут пересекаться. Корни не деформируются под землю, ходьбы по их поверхности нет; столкновения приближают ствол. Художественная приёмка новой расстановки ещё впереди. Подлесок, другие семейства и акварельный рендер пока не готовы.

[Прежнее авторское дерево](https://amchercashin.github.io/drevlepuscha/tree.html?model=game) и [его лес](https://amchercashin.github.io/drevlepuscha/?scene=m1&tree=game) сохранены как контроль: 4818 / 1268 / 268 треугольников, два материала. Старые [замеры](qa/evidence/m1-performance-webgpu.json) и [проверка дальних групп](qa/evidence/m1-horizon-comparison.json) относятся к нему. В том числе проверено восстановление точной позиции камеры после `setTarget`, устраняющее сдвиг на 1 мм.

## Исходная проба дерева

[Осмотреть объёмную модель](https://amchercashin.github.io/drevlepuscha/tree.html): семь ракурсов, свободное вращение, сетка и скачивание самостоятельного GLB с текстурами. Это программная интерпретация приватного листа с ракурсами: 19 280 треугольников, пять материалов, GLB 1,36 МБ; высота около 18 м принята для пробы, путник — 1,1 м. Исходник — `src/domain/reference-tree.ts`; воспроизвести экспорт: `node --experimental-strip-types tools/export-reference-tree.mjs`. Текстуры созданы процедурно, пиксели референса в сборку не входят.

Форма и масштаб доступны для художественной оценки, но акварельный характер пока не достигнут: крона состоит из плотных объёмов, стыки корней видны вблизи. В отдельном просмотрщике исходника нет ветра; игровые LOD и нагрузочная сцена описаны выше; модель относится к верхней границе бюджета дерева-ориентира. Это не завершение M1.

Проверки пробы: `npm run check` — 80 тестов; полный браузерный набор — 26 проверок в Chrome на WebGL2 и WebGPU. Самостоятельный GLB проверен Khronos glTF Validator 2.0.0-dev.3.10: ошибок и предупреждений нет. Ракурсы осмотрены в локальном просмотрщике; импорт в Blender и производительность лесной сцены не проверялись.

## Начать работу

Нужен Node.js **22.23.1**, одинаковый на macOS и Windows. На новой машине сначала выполнить `git clone https://github.com/amchercashin/drevlepuscha.git`, затем открыть папку `drevlepuscha`:

```text
npm ci
npm run doctor
npm run check
npm run dev
```

Открыть [стенд](http://127.0.0.1:5173). Нажать «Начать прогулку»: WASD — движение, правая кнопка мыши — осмотр, колесо — дистанция, Space — камера за спину, Esc — пауза. Кнопки снизу переносят к препятствиям. В панели «Проверка стенда» можно выбрать ракурс и графический режим.

Для стабильной готовой сборки: `npm run build`, затем `npm run preview` и [порт 4173](http://127.0.0.1:4173). Для разработки использовать `dev`; он автоматически перезагружает сцену после изменения исходников.

Все зависимости закреплены локально. `npm run check` выполняет проверку типов, данных и 85 тестов. `npm run test:browser` собирает приложение и проверяет его в установленном Chrome последовательно на WebGL2 и WebGPU.

При подготовке исходный комплект был сокращён с 99 до 47 файлов; M0 добавляет необходимый код и воспроизводимые проверки. Пять художественных референсов и исходный ZIP сохранены отдельно от игровой сборки.

## План разработки

Это рекомендация по объёму следующих этапов. Она сохраняет направление версии 0.3 и заменяет два параллельных плана исходного комплекта.

| Этап | Конкретный результат | Условие перехода |
|---|---|---|
| **M0 — камера и движение** | Лёгкая браузерная сцена: земля, склон, несколько стволов, простая арка и герой около 1,1 м. WASD, вращение, взгляд вверх, возврат камеры, фиксированная дистанция камеры и прозрачность препятствий. | Проход без застреваний и провалов; понятное управление; реальные кадры и замер на этом Mac. |
| **M1 — образ леса** | Короткая тропа и поляна на будущем маршруте Древлепущи. Два-три семейства деревьев, молодая и старая группы, один свет. | Пользователь принимает ощущение масштаба и художественный язык в движении; сцена укладывается в измеренный бюджет. |
| **M2 — первая прогулка** | Западный вход → молодой лес → Bonfire Glade → старый лес → начало южного спуска. Ориентиры, простые открытия, анимация, локальное сохранение и экспорт/импорт. | Человек проходит маршрут без устных подсказок; сохранение восстанавливает состояние; выполнен запуск из чистой копии на Windows. |
| **Затем — расширение** | Второе место из того же набора моделей; по его результатам — генератор, новые сообщества, постепенная детализация леса и атлас. | Повторное производство доказало экономию времени; проверены источники географии и нагрузка. |

У каждого этапа один исполнитель разработки — Codex или разработчик; художественную и игровую приёмку проводит Александр. Проверку на Windows проводит исполнитель с доступом к Windows, приёмку канонической привязки — Александр по выбранному изданию.

Следующая задача — **M1**, форма деревьев и ощущение леса. Выбран путь А; собрана сцена из 4967 вариаций импортированного дерева; художественная приёмка M1 ещё впереди. Необходимость Blender оценить на M1, когда появится конкретная модель для редактирования. Размер участка определяется качеством короткого прохода; прежние 256, 512 и 1024 единицы не являются тремя обязательными картами.

Для будущего бесшовного леса 1:1 подготовлен [план масштаба, моделей и подгрузки](docs/DESIGN.md#большой-бесшовный-лес), включая [требования к траве, рельефу, воде, животным и четырём персонажам](docs/DESIGN.md#требования-к-моделям-и-насыщенной-сцене). Цель — 60 FPS на M3 с 8 ГБ при 1280×720: подробное окружение рядом, упрощённый дальний план, ограниченные память и число активных объектов. С горы должен быть виден ландшафт до горизонта: LOD отдельных деревьев переходит в общие модели рощ и дальнее покрытие; выгрузка подробностей сохраняет видимую замену. Бюджеты предварительные. После художественного образца нужен технический маршрут 1–2 км с открытой вершиной, проверкой подгрузки и 30-минутным замером. Полный размер Древлепущи в метрах ещё не подтверждён; стриминг и дальнее покрытие пока не реализованы.

Для LOD автору достаточно одной исходной модели: упрощения и дальние группы должны вычисляться автоматически по необходимости и кэшироваться. После внутренней пробы штатного упрощателя подготовлена игровая версия 4818 / 1268 / 268 треугольников и первая сцена для проверки качества и нагрузки. [Диспетчер бюджета кадра](docs/DESIGN.md#выбор-кадра-по-общему-бюджету) запланирован с сохранением ближнего качества и горизонта. Его жёсткие лимиты требуют ограничить стоимость самой ближней сцены; такой диспетчер пока не реализован.

В приёмку M0 входят шесть пресетов из [конфигурации камеры](config/camera-presets.json), полный осмотр на месте, взгляд под крону и непрерывная запись прохода. Проверить камеру около ствола, у склона и под аркой, остановку движения при потере фокуса и отсутствие ошибок браузера. Минимальный интерфейс — подсказка управления и диагностические показатели. Атлас на M0 не нужен.

## Критическая оценка

1. **Пакет гораздо подробнее, чем существующая программа.** 57 Markdown-файлов, два обзора и несколько точек старта создавали впечатление большей готовности. Теперь один вход и одна очередь работ.
2. **Красота леса ещё не доказана.** Концепты привлекательны, но не показывают работающий рендер. Сначала нужно убедительное дерево и короткий проход; производство десятков вариантов заранее дорого и может закрепить неудачный стиль.
3. **Смена камеры меняет производство моделей.** С земли видны слабые корни, стволы и нижняя сторона крон. Детализация должна концентрироваться там, куда реально подходит игрок.
4. **География пока схематична.** Семь объектов и границ в данных — заготовка для проверки по источникам. Их нормализованные координаты авторские; метрическая карта не оцифрована.

## Дополнительно

M0 проверяется на MacBook Air M3 с 8 ГБ памяти при внутреннем разрешении не выше 1280×720 и DPR 1. Замеры и границы выводов — в отчёте M0. Длительная нагрузка насыщенного M1 и прогулка на реальном Windows-компьютере ещё не проверены. Установка, тесты и сборка на Windows уже прошли в GitHub Actions. Большие наборы моделей и Blender заранее не устанавливались.

Исходные 99 файлов сохранены целиком в отдельном архиве `Drevlepuscha_Codex_Kit_v0.3_ThirdPerson.zip` вне репозитория. Для повседневной разработки читать его не требуется.

## Работа на разных машинах

GitHub хранит общую историю исходников; разработка выполняется в локальном клоне на каждой машине. Перед началом: `git status`, затем `git pull --ff-only`, `npm ci`. После завершённого изменения: проверки, коммит, `git push`. Если есть незакоммиченные изменения или конфликт, сначала сохранить и согласовать их, не применять `reset --hard` или force-push для обхода проблемы.

Изменения в `main` автоматически проходят проверку типов, данных, 85 тестов и сборку на Linux и Windows. Только после успеха на обеих системах GitHub Actions публикует `dist` на Pages. Для параллельной работы создавать отдельные ветки `codex/<задача>` и объединять их через pull request. Браузерные проверки WebGPU на реальном GPU остаются отдельной проверкой; CI не заменяет их.
