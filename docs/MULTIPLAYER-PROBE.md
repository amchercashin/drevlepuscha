# Сетевая поляна

[Открыть прототип](https://amchercashin.github.io/drevlepuscha/multiplayer.html). Отдельная лёгкая страница с движущимися метками для проверки сети перед переносом мультиплеера в лес.

## Проверка с другом

1. На компьютере откройте страницу без VPN, нажмите «Создать комнату» и скопируйте приглашение.
2. Отправьте ссылку другу либо откройте её на телефоне с мобильным интернетом (Wi-Fi отключён). На обоих устройствах выключите VPN. Ведущий держит исходную вкладку открытой.
3. После подключения двигайтесь мышью, касаниями или WASD/стрелками. Проверьте, что оба видят движения друг друга, в том числе после минуты ожидания и обновления страницы гостя.
4. При ошибке подождите 40 секунд. На обоих устройствах раскройте «Проверка соединения» и сохраните или скопируйте результат. Вместе с результатами укажите сети, браузеры и был ли выключен VPN. Отчёт сам этого не определяет.

Всего четыре участника вместе с ведущим. Пятый получает сообщение о заполненной комнате и может повторить вход после освобождения места. Приглашение позволяет войти любому, у кого есть ссылка. Кнопка выхода ведущего завершает комнату; переноса роли ведущего и сохранения комнаты нет. После закрытия или обновления вкладки ведущего создайте новую комнату.

## Устройство и ограничения

- Страница и весь JavaScript размещаются на GitHub Pages. Собственный сервер не нужен.
- Trystero Core устанавливает WebRTC DataChannel. Публичные MQTT-брокеры Shiftr и EMQX передают служебные сообщения для поиска и соединения; позиции и имена идут через WebRTC. Пароль из фрагмента приглашения используется для защиты сигнализации библиотекой.
- Ведущий соединён с каждым гостем, гости между собой не соединяются. Ведущий принимает координаты и рассылает состояние 15 раз в секунду. Проверяются формат сообщений, координаты, последовательность и число участников. Это прототип совместной прогулки, без защиты игровой логики от недобросовестного участника.
- Адаптер MQTT объявляет комнату каждые 5 секунд: стандартный минутный интервал слишком долог для позднего входа пассивного гостя. Подписки восстанавливаются после переподключения брокера.
- Используются STUN Cloudflare, Twilio и Google. **TURN не настроен:** некоторые пары сетей не смогут соединиться напрямую. Успех MQTT из России не доказывает работоспособность WebRTC через разные сети. При таком сбое следующий шаг — проверить доступный TURN, не переписывая игровую часть.
- Публичные брокеры подходят для этого теста; их доступность и лимиты не гарантированы. Подключения к двум брокерам повышают шанс обнаружения комнаты, но не решают ограничения NAT.
- Отчёт содержит состояния, типы ICE-кандидатов, выбранный маршрут, RTT и ошибки. Приглашение, имена и IP-адреса в отчёт не включаются. Маршрут `direct` на одном компьютере не подтверждает доступ из России между разными сетями.

## Проверки разработчика

```sh
node --experimental-strip-types --test tests/multiplayer.test.mjs
npm run typecheck
npm run dev
node tools/check-multiplayer.mjs http://127.0.0.1:5173/multiplayer.html
```

Последняя команда использует установленный Chrome и реальные публичные сервисы; поэтому не входит в обязательный CI. Проверяет одновременный вход, лимит, топологию, движение в обе стороны, касание, узкую раскладку, обновление гостя, освобождение места, повторный вход и завершение комнаты. Все браузерные контексты работают на одном Mac. Отдельная проверка двух российских сетей без VPN остаётся необходимой перед интеграцией в лес.
