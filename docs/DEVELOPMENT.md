# Рабочий процесс

## Две активные сцены

Шоукейс `/` служит для графики, дизайна и леса. Карта `/?scene=world` — для географии, стриминга и большого мира. Проверка второй сцены нужна, только если задача действительно меняет её поведение. Перенос графических решений на карту — самостоятельная задача.

Старые M0/M1, эксперимент Lite, `tree.html` и сравнения ассетов не являются обязательными целями разработки или приёмки.

## Проверка по задаче

| Что изменено | Достаточная проверка |
| --- | --- |
| Текст, инструкции, документация | Просмотреть diff и затронутые ссылки. Браузер не нужен. |
| Локальная логика | Конкретный относящийся к изменению тест; проверка типов при необходимости. |
| Графика или поведение шоукейса | Один короткий сценарий в шоукейсе, в одном обычном размере окна. |
| География или поведение карты | Один короткий сценарий на карте в нужном месте. |
| Общий запуск, затрагивающий обе активные сцены | По одной проверке запуска каждой сцены. |
| Производительность, мобильное управление, адаптивность или перенос на другую ОС | Только соответствующие условия и устройства. |

Выберите ручную или автоматическую проверку, которая отвечает на конкретный вопрос. Не добавляйте второй способ, другие ракурсы, устройства или разрешения для полноты отчёта. После успешной проверки переходите к публикации; визуальную оценку делает пользователь.

`npm run test:showcase` и `npm run test:map` запускают по одному короткому браузерному сценарию. Они не запускают сборку, старые стенды, просмотрщик дерева, мобильные раскладки или замеры FPS. Используется установленный Chrome, WebGPU, одно окно 1280 × 720. Это техническая проверка работоспособности, а не художественная приёмка.

`npm run check` оставлен для CI и задач, где действительно нужен общий контроль типов, данных и модульных тестов. Не запускайте его автоматически после каждой правки и не повторяйте локально только ради дублирования CI. Полный браузерный набор не является этапом завершения задачи.

Специальные старые тесты сохранены в `tests/browser`. При конкретной диагностической необходимости можно выбрать один файл через `playwright.specialist.config.mjs`. Наличие этих тестов не означает необходимости их запуска. Не запускайте весь специальный набор.

## Локальная работа

Используйте закреплённый Node из `.node-version` и зависимости из lockfile. `npm ci` нужен при первой установке или изменении зависимостей, а не в начале каждого задания. `npm run dev` запускает текущие исходники без сборки всего мира. Если менялась география или её кэш отсутствует, подготовьте данные командой `npm run world:build`.

Для публикации используется `npm run build`. Он готовит данные и статическую сборку. Не запускайте сборку второй раз, если исходники не изменились и результат уже готов. Одновременно выполняйте только одну графическую проверку; обычная задача не требует установки новых браузеров, инструментов или пакетов моделей.

## Публикация

После адресной проверки сохраняйте относящиеся к задаче изменения и отправляйте их в `main` для GitHub Pages. Ветка карты может сохраняться отдельно; не переносите между направлениями изменения, не входящие в задачу. Не перезаписывайте чужие незакоммиченные файлы и не используйте force-push.

CI проверяет данные и модульные тесты, затем выполняет одну сборку на Linux. Проверка типов входит в сборку и не дублируется. Чисто текстовые правки и материалы QA не запускают CI. Браузерные проверки и Windows в обязательную CI-матрицу не входят. Пользователю сообщайте результат и ссылку для визуальной оценки, без автоматической серии скриншотов и видео.

## Технические справки

Коллизия процедурной модели строится из геометрии выбранного варианта через `collisionGeometry`, один раз на вариант. Для экземпляра передавайте в `meshCollider` итоговую матрицу отрисовки и её обратную: так масштаб по каждой оси, поворот, наклон и заглубление совпадают с изображением. Коллизия использует LOD0 независимо от переключения видимого LOD. После изменения геометрии пересоздайте её данные коллизии; после изменения трансформации пересоздайте коллайдер и обновите пространственный индекс. Это требуется и для изменений во время игры: замороженные матрицы и статический индекс сами не обновляются. Старые `trunkRadius` и прямоугольные области остаются приближениями для размещения растительности, а не формой физического препятствия у моделей с `collision`.

Художественные, камерные и географические решения — в [DESIGN.md](DESIGN.md); читать только относящиеся к задаче разделы. Устройство прежних инструментов, профили измерений и результаты — в [исторической справке](history/DEVELOPMENT-before-scope-cleanup.md). Описанные там планы и наборы проверок не являются текущими инструкциями.
