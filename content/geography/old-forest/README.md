# География Древлепущи · v1

**Открыть [атлас](generated/atlas.html).** Это основа для интеграции: 27 объектов и линий, связанная речная сеть, маршрут и готовый численный рельеф. Игровая сцена пока использует прежний участок M1.

## Что считается установленным

Книжные связи сверены с *The Lord of the Rings*, HarperCollins 2005 / eBook 2009, ISBN 978-0-06-191780-6, I.5–I.8, по доступной копии указанного издания. Карту *A Part of the Shire* и карту Стрейчи осмотрели по репродукциям. Подлинность экземпляров у издателя не проверялась. Адреса, локаторы, решения по расхождениям и пробелы проверки записаны в [geography.json](geography.json) и общем [реестре источников](../../../references/sources.json).

**Численные координаты и высоты не канонические.** Западная география опирается на книжную карту, внутренние расстояния — на милевую сетку Стрейчи. Совместить все карты буквально нельзя: верхнее течение Ветлянки противоречиво. Выбрано преимущественно западное верховье с юго-западным низовьем; выход с холма сначала направлен на север, как в тексте. Дом расположен на северной стороне воды, вне леса; его окружение согласовано с Фонстад. Её текст проверен, контуры её карты не оцифрованы. ArdaCraft просмотрен как адаптация, его координаты не использованы.

Граница полного леса и высоты достроены автором реконструкции. В рабочей версии лес занимает примерно **718 км²**, рамка с окружающими землями — **40,96 × 45,056 км**. Это не две оценки одного размера: площадь считается по полигону, рамка включает Бакленд, внешние склоны и часть Брендивайна. Рабочий допуск масштаба ±20 % выбран автором и не является статистической оценкой.

Маршрут — около **43 км**, примерно **6,5 часа** чистой ходьбы при 1,85 м/с; литературное путешествие включает пони, блуждание и остановки. Его длина не доказывает точность реконструкции. Время и масштаб не сокращены ради M1. Вне основного маршрута пути не объявлены исчерпывающей сетью: топология отражает одну осеннюю конфигурацию леса.

## Состав и контракт

| Файл | Назначение |
|---|---|
| `geography.json` | Единственный редактируемый источник геометрии, утверждений, ограничений, рельефа и правил наполнения. |
| `generated/manifest.json` | Метаданные сеток, смещения тайлов, SHA-256, профили, высоты ориентиров и измеренные размеры результата. |
| `generated/base.f32.gz` | Весь регион, узлы через 16 м. |
| `generated/detail.f32.gz` | Уточнения через 2 м вдоль путей, воды и у ориентиров. Брендивайн вне устья остаётся контекстом с шагом 16 м. |
| `generated/atlas.html` | Самодостаточный атлас без сервера и внешних загрузок; построен из того же JSON и рельефа. |

`schemaVersion=1`, версии контента и генератора независимы. `regionId=old-forest`. ID прежних семи объектов сохранены, но старые нормализованные файлы не переписаны и не масштабированы. Этот пакет не подключён к старому `world.manifest.json`: заменить его содержимое автоматически нельзя, у него другой контракт.

Координаты `[e,n]` — метры на восток и север, `h` — вверх. Начало — устье Ветлянки; `h=0` — условный уровень воды в устье, не уровень моря. Геометрия использует `Point`, `LineString`, `Polygon`; это **не GeoJSON/WGS84**. Babylon получает `x=e-origin.e`, `y=h-origin.h`, `z=origin.n-n` через существующий доменный контракт.

Существование и геометрия имеют раздельное происхождение. `canonical` относится к подтверждённому объекту или отношению, а не к точной форме. `inferred` — реконструкция; `authored` — добавление. `uncertaintyM` относится к положению реконструированного объекта на общей карте, не к размеру модели и не к радиусу случайного перемещения. Перемещать закреплённые объекты при каждом seed нельзя. Ссылки на главы в `evidence.locator` используют печатные страницы; реестр дополнительно содержит номера страниц PDF.

### Высоты и импорт

После gzip-декодирования: IEEE-754 Float32 little-endian, метры. Узлы включают обе крайние границы; строки идут **с юга на север**, столбцы — с запада на восток. Индекс `row * columns + column`. Heightfield обычно хранит обратный порядок строк: проверить при импорте, не отражать север молча. Исходные высоты квантованы с шагом 1/64 м для компактности, переходы интерполированы; это точность хранения, не точность источников.

Базовая сетка — 2561 × 2817 узлов. Детальный тайл — 512 × 512 м, 257 × 257 узлов. `detail.f32.gz` состоит из последовательных независимых gzip-members. Для тайла взять `[byteOffset, byteOffset + byteLength)` из файла, распаковать и читать его локальную сетку. `decodedByteOffset` нужен только при распаковке всего файла целиком. `sha256` тайла относится к его сжатому диапазону, общий хеш — ко всему сжатому файлу.

На границе тайлов совпадают общие узлы. У внешней границы области детализации поверхность за 32 м сводится к билинейной базовой сетке; рядом с водой запас выбора тайлов — 48 м. Визуальное совпадение LOD-мешей дополнительно зависит от триангуляции и стыковки рендерера. Нельзя обещать отсутствие трещин у произвольного импортёра.

Рабочий импортёр с кэшем восьми тайлов: `tools/geography/read-heightmap.mjs`. Пример из корня репозитория:

```js
import { openHeightmap } from './tools/geography/read-heightmap.mjs';
const map = openHeightmap('content/geography/old-forest/generated');
try {
  const houseHeight = map.sample(22400, 19350);
  console.log(houseHeight); // метры над условным нулём
} finally {
  map.close();
}
```

Доменный модуль `src/domain/geography.mjs` не зависит от файловой системы, Babylon или DOM: `createGeography(data)` предоставляет `height`, `slope`, `zoneAt`, `exclusion`; `sampleRaster` читает декодированную сетку. Для браузера базовую сетку загрузить один раз, детальные диапазоны — по необходимости; если сервер не поддерживает Range, разделить члены gzip на отдельные файлы на этапе интеграции. Не распаковывать все уточнения в память постоянно.

Рельеф — поверхность земли, включая дно. Вода создаётся **отдельно** по `water.stations`, упорядоченным вниз по течению; третья координата — уровень поверхности воды. У устьев совпадают координаты и уровни родительской реки. Ширины, глубины, размеры поймы и омута авторские. Небольшой водопад имеет заданный перепад в продольном профиле; его художественную геометрию и пену строит runtime.

Heightfield не содержит тоннель под изгородью: проход зарезервирован, но свод, отверстие и столкновения требуют отдельной геометрии. Также это не гидрологическая симуляция всех осадков: проверяются заданные водотоки, а не отсутствие любых замкнутых понижений во всём ландшафте.

### Как наполнять лес

1. Построить рельеф, воду и линии границ.
2. Закрепить ориентиры и их резервы. У дома задан азимут фасада; ближайшие сады размещаются относительно дома. Радиусы резервов и вся точная геометрия авторские.
3. Зарезервировать коридоры маршрутов. Начальный проход без устойчивой тропы не превращать в мощёную дорогу. Небольшое заглубление применяется только к отмеченным сегментам.
4. Выбирать зону с наибольшим `priority`, затем проверять `exclusion`, уклон и сухость грунта. Плотность задана в деревьях/м² как начальный диапазон, не гарантия производительности. Для больших деревьев проверять весь отпечаток, а не только центр.
5. Получать seed из `worldSeed / zoneId / индексы 32-метровой ячейки / номер кандидата`. Результат не должен зависеть от порядка посещения ячеек. `placementSeed` фиксирует FNV-1a для строки ключа; `hash01` даёт числовой поток для параметров кандидата.

Общие правила — мозаика взрослых деревьев, окон крон, возобновления и валежника. Северные хвойные склоны не распространять на весь лес. Корни учитывать по возрасту, плохому дренажу и эрозии, а не только по крутизне. У входа оставить участки без подлеска. Два дополнительных притока явно авторские; ручей в основной лощине подтверждён текстом. Конкретные деревья вне резервов ещё не расставлены.

## Воспроизводимость и приёмка

Из корня, с закреплёнными зависимостями проекта:

```text
node tools/geography/build.mjs
npm run check
node tools/geography/qa-atlas.mjs
```

Сборщик сначала проверяет структуру и источники, затем строит оба уровня высот, профили и атлас. Все `generated`-файлы поставляются готовыми, поэтому обычный запуск приложения не требует повторной генерации. Проверки `npm run check` сверяют входной хеш, сжатые файлы, диапазоны, швы, импортированные высоты, порядок ориентиров, сток и сухость маршрута. Не генерировать эти файлы во время runtime-прогулки.

При интеграции сначала проверить маленькие участки: вход, выход ручья, берег Ива и луг у дома. Затем подключать потоковую загрузку всего региона. Существующие настройки камеры сохраняются. Приёмка в движении, FPS, реальные растительные модели, корректность тоннеля и Windows-запуск этой карты ещё не выполнены; они не следуют из успешного импорта чисел.
