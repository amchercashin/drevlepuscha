# Древлепуща · игровая география 2.0

**Ветка `codex/old-forest-compressed-map`.** [Самостоятельный атлас](generated/atlas.html) содержит текущую карту. Эта ветка меняет географию и её инструменты, не опубликованную игру, не соседний стриминговый мир и не шоукейс.

## Что получилось

Основной путь — **13,35 км**, около **2 часов** чистой ходьбы при 1,85 м/с и **14 мин 50 с** при 15 м/с. Остановки и столкновения с игровыми объектами в этот расчёт не входят. Четыре обходных петли и два тупиковых ответвления дают ещё **3,60 км геометрии троп**; возврат из тупиков увеличивает пройденную длину. Петли заменяют часть основного пути, поэтому прибавлять все 3,60 км к нему как время одного прохождения неверно.

Лес — **130,33 км²** внутри простой границы. Рамка с окрестностями — **27,648 × 35,84 км**. Прежние 105,12 км² первого сжатия считались по самопересекающемуся полигону: его западная граница исправлена, а не расширена ради новых сцен. Исправлены также заворот Брендивайна и положение северного притока после прежней деформации.

| Ответвление | Устройство | Длина тропы |
|---|---|---:|
| Корневая щель | Узкая обходная ложбина, прикрытый вход | 562 м |
| Папоротниковая чаша | Короткий уход в укрытую чашу; возвращение тем же путём | 179 м |
| Скрытая седловина | Обход через понижение между плечами склона | 758 м |
| Тихий амфитеатр | Боковая петля над основной лощиной | 1 041 м |
| Верхняя береговая тропа | Отдельная полка выше речной долины | 981 м |
| Окно к водопаду | Короткий выход к точке обзора; возвращение назад | 83 м |

Названия — **авторские игровые места**, не новые утверждения о тексте Толкина. Папоротники, корни, деревья, камни, видимость воды сквозь растительность и окончательный свет ещё требуют художественного наполнения в игре. На этом этапе реализованы формы земли, русла, пути и резервы.

В карте 39 объектов и линий, 9 зон, 29 крупных и локальных форм рельефа, 12 извилистых систем бортов. Глубина и ширина ложбин меняются вдоль пути; стороны не зеркальны. Оригинальные ключевые сцены защищены от добавочной скульптуры. Реки, пути и зоны получили согласованную мелкую извилистость; слияния водотоков и их уровни сохраняются.

## Масштаб и источники

**Это больше не 1:1.** Историческая реконструкция опиралась на текст I.5–I.8, книжную карту, Стрейчи и сопоставление с Фонстад. Сведения о проверке, расхождениях и допущениях сохранены в `geography.json` и `references/sources.json`. Оригинальная калибровка относится к исходной реконструкции, не к нынешним игровым расстояниям. Её ±20 % нельзя выдавать за точность этой карты.

`canonical` у сохранённого объекта означает подтверждённое существование или связь, не точность формы. Все координаты и высоты реконструированы или авторские. Рельеф не является гидрологической симуляцией всей территории: проверяется заданная речная сеть, а не сток каждой капли осадков.

## Файлы и контракт импорта

`geography.json` — редактируемый источник. `generated/manifest.json` хранит версии, хеши, профили, актуальные размеры и объёмы. `generated/atlas.html` открывается без сервера; это тот же рельеф и те же данные, не отдельно нарисованная карта.

Координаты `[e,n]` — метры на восток и север; `h` — вверх. Горизонтальная система после сжатия сохраняет авторскую сетку: устье больше не имеет координат `[0,0]`. Ноль высоты остаётся условным уровнем воды устья Ветлянки. Это не WGS84/GeoJSON. Преобразование в Babylon: `x=e-origin.e`, `y=h-origin.h`, `z=origin.n-n`.

Базовая сетка `base.f32.gz` — **1729 × 2241** узел через 16 м. Уточнения `detail.f32.gz` — **145 тайлов** по 512 × 512 м, по 257 × 257 узлов через 2 м. Строки с юга на север, столбцы с запада на восток, включены обе крайние границы; Float32 little-endian, метры. После распаковки `index = row * columns + column`. Высоты квантованы через 1/64 м: это точность хранения, не точность источников.

Уточнения состоят из независимых gzip-members. Для одного тайла читать диапазон `[byteOffset, byteOffset + byteLength)`, распаковывать отдельно и сверять SHA-256. На внешнем краю уточнения за 32 м сводятся к билинейной базовой сетке. Стыки чисел проверены; стыковка треугольников и LOD зависит от импортёра. Не распаковывать и не рисовать весь подробный регион одновременно.

Рабочий Node-импортёр `tools/geography/read-heightmap.mjs` кэширует восемь тайлов. Высоты POI брать по его текущим координатам, не по координатам старой версии:

```js
import { readFileSync } from 'node:fs';
import { openHeightmap } from './tools/geography/read-heightmap.mjs';
const g = JSON.parse(readFileSync('content/geography/old-forest/geography.json'));
const house = g.features.find(f => f.id === 'tom_house').geometry.coordinates;
const map = openHeightmap('content/geography/old-forest/generated');
try { console.log(map.sample(...house)); } finally { map.close(); }
```

`map.patch128(e,n)` возвращает 65 × 65 узлов через 2 м; начало должно быть кратно 128 м. Файл хранения 512 м не задаёт размер runtime-чанка. Синхронный Node-импортёр не предназначен для главного потока браузера.

Вода создаётся отдельно по `water.stations`, вниз по течению. Рельеф содержит дно, не поверхность воды. Тоннель под изгородью, навесы, корневые арки, водопадная пена и столкновения с предметами не представлены одной картой высот.

### Дополнительные поля редакции 2.0

`terrain.sculpt.ribbons` задаёт авторские борта ложбин; запросы пространственно индексированы и плавно сходят к нулю на границе влияния. `terrain.landforms[].rotationDeg` поворачивает локальные чаши и плечи. `route.surface.stations` содержит согласованный высотный профиль узкой пешеходной полки. У поворотов и соединений переходы смешиваются; русло при этом не засыпается. Эти поля исполняет текущий `src/domain/geography.mjs`, не любой старый импортёр.

`route.hidden` и `discovery.initiallyHidden` — **метаданные для будущего игрового обнаружения**, а не реализованный туман войны. В редакторском атласе авторские тропы видны пунктиром. `dressing` остаётся заданием на растительность и детали, не готовыми моделями. При интеграции сохранять резервы POI, свободные тропы, воду и приоритеты зон.

## Проверки и просмотр

Обычный цикл после изменения географии из корня проекта:

```text
node tools/geography/grade-paths.mjs
node tools/geography/build.mjs
npm run check
node tools/geography/qa-atlas.mjs
```

Первую команду выполнять при изменении формы маршрута или исходного рельефа: она пересчитывает полки с проектным уклоном до 30 %, не меняя критерий проверки. `curve-geography.mjs` — однократный инструмент авторской деформации; **не запускать повторно на этой карте**, где `terrain.curvature` уже заполнено. Для воспроизведения текущей версии достаточно готового JSON и сборщика; версия первого сжатия сохранена в коммите `f3f920e`, а текущий JSON уже содержит все авторские изменения.

3D-просмотр рельефа: запустить `npm run dev -- --port 4281`, открыть `/tools/geography/relief-preview.html`. Шесть локальных участков 480 × 480 м, настоящий вертикальный масштаб, обзор/уровень тропы и свободное вращение. Это техническая сцена земли и воды без лесных моделей и окончательного света. Снимки и браузерный отчёт — `qa/evidence/map-stage2/`; повтор проверки — `node tools/geography/qa-relief.mjs`. Другой порт задаётся через `RELIEF_URL`.

**Проверено:** `npm run check` — 105 тестов. Включены отсутствие самопересечений границы, источники, порядок оригинальных мест, слияния рек и монотонные уровни, детерминизм, импорт, хеши, стыки тайлов. Все девять маршрутов проверяются на сухость и максимальный уклон **менее 45 % в экспортированной карте высот** с шагом не более метра. Измеренный максимум по всем маршрутам — **31,1 %**, подводных проб нет; числа и область проверки записаны в `qa/evidence/map-stage2/geometry.json`. Порог старого теста не ослаблен. Старые абсолютные координаты тестов заменены текущими именованными объектами.

Атлас проверяется на поиск, карточки, слои, выбор объектов, профиль, скачивание JSON, ширину 390 px и отсутствие ошибок. 3D-просмотр проверяется последовательно на всех шести участках, с орбитальным движением камеры и ракурсом у земли. Данные о числе мешей относятся только к этой отдельной технической сцене.

**Не проверено этим этапом:** непрерывная прогулка персонажа в стриминговом лесу, коллизии с деревьями, итоговая растительность, закрытость секретов кронами, игровой FPS, Windows и реальный iPhone. Соседняя ветка игры и опубликованные Pages не обновлялись. Художественную приёмку леса нужно проводить после интеграции карты в игровое окружение; по одному рельефу её объявлять нельзя.
